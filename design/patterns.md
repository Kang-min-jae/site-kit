# patterns.md — 페이지 패턴

각 패턴은 **영역(무엇이 어디에) → 크기 → 쓰는 부품 → 반응형 → 하지 않을 것** 순서로 적었다. 숫자 단위는 px, 크기 이름은 tokens.css.
공통: 맨 위 `SiteHeader`(높이 64), 맨 아래 푸터(이름·필수 링크·연락처, `body-sm`, ink-3). 섹션 사이 96(모바일 64).

---

## 1. 랜딩 · 첫 화면

### A형 — 쓰는 사이트 (서비스·쇼핑·예약)
```
┌ Header ─────────────────────────────────────────────┐
│ 이름                         메뉴 메뉴 메뉴   [행동] │
├─────────────────────────────────────────────────────┤
│ 무엇을 누구에게 (display, 2줄 이내)  │ 실제 화면/상품 │
│ 보조 한 줄 (body, ink-2)            │  이미지 (크게)  │
│ [주 행동]  안심 한 줄(label, ink-3)  │                │
└─────────────────────────────────────────────────────┘
  ↓ 2등: 실제 내용 미리보기 (카드 3~4개 or 검색칸)  ← 첫 화면 아래 끝이 살짝 보이게
  ↓ 3등: 이유 3개 (아이콘 없이 제목 title-sm + 한 줄)
  ↓ 마지막: 주 행동 반복 1회
```
- 왼쪽 글 5열 / 오른쪽 그림 7열. 모바일: 글 → 그림 → 행동 순 한 열.
- 큰 문장에 핵심 단어와 보조 단어를 **같은 크기, 다른 밝기**(ink / ink-3)로 쓸 수 있다.
- "실용적인·빠른" brief면 그림 대신 검색칸을 첫 화면에 둔다.

### B형 — 보여주는 사이트 (포트폴리오·작품·초대장)
```
┌ Header (투명, 이름 + 메뉴 버튼) ────────────────────┐
│ 한 줄 소개 (display-lg)                             │
│ 무엇을 하는 사람/곳인지 (body, ink-2)               │
├─────────────────────────────────────────────────────┤
│ [작업] [작업] [작업]   ← 같은 비율 카드, 첫 화면에서 보임 │
│ [작업] [작업] [작업]                                 │
└─────────────────────────────────────────────────────┘
```
- 첫 화면 높이의 40% 안에 작업물이 보이기 시작해야 한다 (P2).
- 카드를 누르면 `Dialog`(lg)로 짧은 상세 → 큰 미디어 + 한 줄 + 행동 1 + 같은 모양 관련 작업 3개.
- 의도적 엇갈림(사진 높이 다르게)은 한 섹션만.

### C형 — 무대형 (내용물 하나가 화면 전부, 글은 거의 없음)
"세련된·깔끔한"이 **아주 강한** 사이트(내 취향, R19). 보여줄 내용물(작품·모형·제품) 자체가 첫 화면을 다 차지하고, 설명은 메뉴로 보낸다.
```
┌ Header (투명) ─────────────────────────────────────────────┐
│ 이름                메뉴 · 메뉴 · 메뉴 (가운데)              │
├────────────────────────────────────────────────────────────┤
│ 큰 이름(display, 명조)                                      │
│ 라벨 ── 값                                                 │
│ 라벨 ── 값      ┌──────── 내용물(화면 끝까지) ────────┐     │
│ 라벨 ── 값      │   끌기·누르기에 반응하는 실제 내용    │     │
│                 └──────────────────────────────────────┘     │
│                     짧은 이름표 (eyebrow, 한 줄)              │
│                        [하는 일 하나]                        │
│                     보조 한 줄(label)          조작 안내(label)│
└────────────────────────────────────────────────────────────┘
  (스크롤 아래 섹션 없음 — 사용법·소개는 메뉴 페이지로)
```
- 첫 화면의 글: 큰 이름 1개 + 라벨-값 표(4줄 이하) + 이름표 한 줄 + 버튼 + 안내 한 줄. **문단 금지.**
- 무대 높이 = 화면 높이 − 머리(4rem). 내용물은 화면 끝까지(full-bleed), 글·버튼은 본문 폭(`container-page`)에 맞춘다.
- 내용물은 사용자에게 반응한다: 끌기(돌리기), 누르기(가까이), 마우스 쪽으로 살짝 기울기(최대 약 7°). 혼자 계속 도는 것은 금지(8장).
- 파일을 받는 사이트면 **화면 어디에 끌어다 놓아도** 받고, 끌고 들어오면 무대 전체가 받는 자리로 바뀐다.
- 머리 메뉴는 가운데(`SiteHeader navAlign="center"`), 3개 안팎.
- [하는 일] 버튼은 기본 크기(md). 내용물보다 커 보이면 안 된다(2차 부품 평가).
- 모바일: 표는 숨기고 내용물 + 행동 하나만.
- 저작권: 참고한 사이트의 **내용물 모양·배치(예: 원판을 사선으로 늘어놓기)·글꼴·색 값은 쓰지 않는다**. "내용물이 주인공, 글은 구석에 작게, 메뉴는 가운데"라는 원리만.
- v0.2: editorial·object 디렉션(`directions.md`)의 첫 화면이 이 C형이다. 라벨-값 표는 `SpecList`, 처음 한 번의 등장은 `Reveal`(움직임 줄이기면 바로 완성 상태).
- **도구형 변형** (만들기·고치기 화면): 같은 무대 위에 도구를 가장자리로 — 위 가운데 보기 전환(알약 토글 하나), 오른쪽 가장자리 도구(4개 이하), 왼쪽 아래 범례·안내, 오른쪽 아래 주 행동 하나. 틀은 `ObjectStage`. 고칠 값이 많으면 오른쪽에 패널 하나(옆 단 1개 — DESIGN 4장)로 두고, 패널 안은 상자 대신 선과 여백으로 나눈다.
  - **무대 + 패널** (v0.2.1, Auto-BIM 작업·건물 화면): 무대가 화면 전체가 아니라 12칸 중 8칸일 때. 무대는 테두리 없이 바탕색만(`relative` 바깥 틀 안에 고정 비율 칸), 위 왼쪽에 보기 전환 `Segmented floating`, 아래 가장자리에 `StageBar`(시점·단면·보이기 — 좁은 화면에선 무대 아래로 내려온다). 무대 아래에 색 설명 한 줄 + `SpecList layout="row"`. 옆 4칸 패널은 `PanelSection` 번호 묶음(01 고칠 값 → … → 마지막 = 적용)이고, 패널 첫 선을 무대 윗선에 맞춘다. 주 버튼은 제목 줄에 하나(받기) — 고칠 내용이 생기면 주 버튼이 패널의 "적용"으로 넘어간다.
  - 창 안에서 그리는 도구(계단·벽 그리기)는 `Dialog size="xl"` — 그리는 칸 8 + 설정 4.
  - 무대 위 결과 표시(검토 결과·오류·확인 필요)는 글 상자 대신 **번호 표식**만 두고, 설명은 옆 패널 목록에 같은 번호로 둔다. 표식을 누르면 그 줄이 펼쳐지고, 줄을 누르면 무대가 그 자리로 간다. 진행 상태 표시는 무대 오른쪽 위 가장자리에 잠깐. 왜: Auto-BIM 위험 검토에서 3D 위 설명 상자 여러 개가 좁은 무대에서 서로·모형·층 이름표를 덮었다 — "보기 힘드네, 더 가독성 좋고 보기 편하게"(2026-10-30).

### D형 — 풀블리드형 (v0.2 · house 디렉션)
```
┌ FullBleedMedia (화면 높이 88~100%) ──────────────────┐
│ [헤더: 투명 · 워드마크 · micro 메뉴 · 예약]           │
│                                                     │
│                 실제 소재 (정물·공간·작품)            │
│                                                     │
│ MICRO LABEL                                         │
│ 큰 한 줄 (display-xl, 2줄 이내)                      │
│ 사실 한 줄 (위치 · 시간)   [주 행동]                  │
└─────────────────────────────────────────────────────┘
  ↓ EditorialSplit: 사진 4/5 │ 라벨 → 제목 → 문단 ≤2 → SpecList(align="start")
  ↓ 글자 목록(MenuList / IndexList) + DragGallery 한 줄
  ↓ 어두운 섹션 1개 (방문 정보 또는 영상)
  ↓ 마지막: 주 행동 반복 1회
```
- 글자는 왼쪽 아래 한 덩어리. 소재의 가장 밝은 부분과 겹치지 않게 아래쪽에 어둡게 깔기(scrim)를 둔다 → 대비 4.5:1(F).
- 주 행동 버튼은 기본 크기(md). 큰 버튼(lg)은 소재와 크기를 다퉈 싸 보인다(2차 부품 평가: "버튼이 너무 커").
- 첫 화면에서 "무슨 곳, 어디, 언제, 무엇을 하면 되는지"가 다 보여야 한다(P1). 분위기만 있고 사실이 없으면 실패.
- 모바일: 소재 높이 72svh → 글자는 소재 아래가 아니라 소재 위 아래쪽에 그대로. 큰 한 줄은 `display-xl`이 48부터 시작.

**하지 않을 것**: 추상 장식 히어로, 스크롤 가로채기, 긴 소개 애니메이션, 자동 재생 슬라이드.

## 2. 목록

```
┌ 페이지 제목 (title-lg) ─────────── 총 N개 ────────────┐
├──────────┬──────────────────────────────────────────┤
│ 분류     │ ResultBar: 총 128개            정렬 ▾    │
│ ─ 전체   │ [켜진 필터 칩 ×] [모두 해제]               │
│ ─ 상의 ● │ ┌────┐ ┌────┐ ┌────┐ ┌────┐                │
│ 필터     │ │카드│ │카드│ │카드│ │카드│   ← 같은 비율    │
│ □ 가격대 │ └────┘ └────┘ └────┘ └────┘                │
│ □ 색     │ ...                                       │
│ (240px)  │ [더 보기] 또는 쪽 번호                     │
└──────────┴──────────────────────────────────────────┘
```
- 옆 단 240px 고정, 결과 영역 열 수: ≥1280 4열 / ≥1024 3열 / ≥640 2열 / 모바일 2열(상품) 또는 1열(글·작품).
- 카드 사이 가로 16~24, 세로 40.
- 선택된 분류는 굵게 + 앞에 점. 묶음 사이는 굵은 선 1줄 또는 여백 32.
- 모바일: 옆 단 → 위쪽 가로 스크롤 `Chip` 줄 + "필터" 버튼(아래 시트 `Dialog`).
- **browse**(둘러보기): 이미지 + 제목 + 한 줄. 끌어서 넘기는 가로 줄은 섹션당 1개까지.
- **compare**(비교): 가격 가장 크게, 할인율만 강조색, 정보 순서 고정.
- 불러오는 중: `SkeletonCard` 같은 개수. 결과 없음: `EmptyState kind="no-results"`.

## 3. 상세

### 짧은 상세 (창) — 보여주는 사이트, 목록 흐름을 끊지 않을 때
- `Dialog size="lg"`: 큰 미디어(16/9 또는 원 비율) → 제목(title) → 한 줄(body, ink-2) → 행동 1 → 관련 카드 3개(같은 모양).
- 닫으면 목록의 같은 자리로 돌아간다. URL도 바뀌게(공유 가능) — Next.js 가로채기 경로.

### 단독 상세 — 쓰는 사이트 (상품·수업·책)
```
┌──────────────────────────────┬─────────────────────┐
│ 사진 1 (크게)                │ 분류 (eyebrow)       │
│                              │ 이름 (display-sm)    │
│ 사진 2                       │ 가격                 │
│                              │ 옵션: 색 견본 ●●○    │
│ 사진 3                       │ 사이즈 [S][M][L] 가이드│
│ (세로로 쌓기, 7열)            │ [주 행동 (block)]    │
│                              │ 배송·환불 한 줄씩     │
│                              │ (5열, 위에 붙어 따라옴)│
├──────────────────────────────┴─────────────────────┤
│ Tabs: 상세 | 사이즈·소재 | 배송·교환 | 후기 12        │
│ 비슷한 것 (같은 모양 카드 4개)                        │
└────────────────────────────────────────────────────┘
```
- 정보 단은 `sticky top-24`로 따라온다.
- 옵션을 다 고르기 전엔 주 행동이 잠기고 `disabledReason="사이즈를 고르면 담을 수 있어요"`.
- 모바일: 사진 가로 넘김(점 표시) → 정보 → 하단 고정 주 행동 바(높이 72, 바탕 surface + 위 선).
- 가격 표현은 프리셋을 따른다: calm=이름과 같은 크기, friendly=title-sm 굵게.

### 작품·인물처럼 "정보 + 평가"가 있는 상세 (calm에 잘 맞음)
```
┌──────────────────────┐                ┌ 목록 패널 (각진 상자, 내용 크기) ┐
│ 제목 (display, 제목 글꼴) │                │ 항목                          │
│ ──────────────────── │                │ ■ 지금 항목          2024 ■   │ ← 반전 막대
│ 감독         이름     │ ← 라벨-값 표     │ 항목                          │
│ ──────────────────── │                └──────────────────────────────┘
│ 연도         2024     │
│ ──────────────────── │       큰 이미지·작품 (주인공)
│ 출연         이름…     │
└──────────────────────┘
          ★★★★★                       ★★★★★
         출처 라벨                      출처 라벨
   "인용문 (제목 글꼴, 크게)"        "인용문"
```
- **라벨-값 표**: 라벨은 `eyebrow`(작은 대문자·넓은 자간, 왼쪽), 값은 오른쪽 정렬 `body`, 줄마다 1px 선. 칸이 여러 값이면 값만 줄을 바꾼다.
- **목록 패널**: 같은 종류의 다른 항목으로 바로 건너가는 작은 패널. "개수 ⌃" 버튼으로 열고 닫는다. 지금 항목은 반전 막대(바탕 ink, 글자 bg) + 오른쪽에 보조 정보 하나(연도 등). 패널은 각진 상자, 내용에 맞는 크기, 얇은 스크롤 막대.
- **평가·인용**: 출처(작은 라벨) → 인용문(제목 글꼴, `title-lg`) → 별점 순서(2차 부품 평가: "별점이 인용 아래로"). 2~3개를 같은 폭으로 나란히. 출처와 인용문은 실제로 받은 것만 쓴다(지어내지 않는다).
- 바탕은 무채색(회색·미색), 색은 작품 이미지가 낸다. UI는 흑백, 모서리는 한 가지로 통일.
- 움직임은 목록에서 고르면 큰 이미지가 바뀌는 정도까지. 혼자 도는 연출은 쓰지 않는다.
- 하지 않을 것: 참고한 사이트의 시그니처 연출(작품을 특정 물건 모양으로 늘어놓는 방식)은 따라 하지 않는다 — 우리 사이트만의 "작품 보여주는 방식"을 새로 정한다.
- 부품(v0.2): 라벨-값 표 = `SpecList`, 평가·인용 = `PressQuote`(실제 평가만 — 시안에서는 `sample`로 "예시" 표시), 목록 패널 = `IndexList`.

## 4. 글 읽기
```
       분류 · 날짜 (label, ink-3)
       제목 (display-sm, 3줄 이내)
       한 줄 요약 (body, ink-2)
       글쓴이 (작은 원형 사진 32 + 이름)
       ───────────────
       본문 (prose-reading, 최대 700)
       소제목 h2: 위 64 / 아래 20
       그림: 본문 폭 그대로 또는 좌우로 조금 넓게(최대 880), 설명 caption
       ───────────────
       다음 글 2개 (카드)
```
- 목차는 글이 소제목 5개 이상일 때만, 1280px 이상 화면의 오른쪽 여백에.
- 본문 안 강조는 굵게만. 색 글씨·형광펜 금지.
- 읽는 위치 표시가 필요하면 맨 위 2px 진행 막대 하나.

## 5. 로그인 · 가입
- **전용 페이지(friendly 기본)**: 화면 가운데 카드(최대 400). 이름(로고) → 제목 "로그인" → 이메일 칸 하나 → [계속하기] → 구분선 "또는" → 소셜 버튼(같은 크기, 세로로) → 아래 "처음이에요? 가입하기".
- **창(calm 기본)**: 보던 화면 위 `Dialog`. 로그인/가입 전환 링크는 같은 자리에서 내용만 바뀐다.
- 이메일 먼저 받고, 있는 계정이면 비밀번호 / 없으면 가입으로 이어간다 (입구 하나).
- 소셜은 한국 사이트면 카카오·네이버·구글 순. 각 서비스의 **공식 버튼 가이드**를 따른다(로고를 직접 그리지 않는다).
- 로그인 화면에서는 주 메뉴를 숨긴다. 로그인 뒤 원래 가려던 곳(`next`)으로.
- 가입 동의는 `ConsentGroup`. 비밀번호는 보기 버튼, 조건은 칸 아래에 미리 보여주고 만족하면 체크로 바뀐다.

## 6. 폼 · 결제 (여러 단계)
```
Stepper (1 정보 ─ 2 결제 ─ 3 완료)
┌───────────────────────────────┬──────────────────┐
│ 입력 (7열)                    │ 요약 (5열, sticky)│
│ 이름 [    ]  연락처 [    ]    │ 상품·수량         │
│ 주소 [                    ]   │ 합계 (title, 굵게)│
│                               │ [결제하기 32,000원]│
│                               │ 안전 결제·환불 안내│
└───────────────────────────────┴──────────────────┘
```
- 관련 칸은 둘씩 짝(이름+연락처). 한 단계 칸 6개 이하.
- 결정 버튼 바로 아래에 안심 정보(환불·해지·보안) 한 줄씩. 법적 문구는 그 아래 떨어뜨려 caption.
- 오류는 제출할 때 첫 오류 칸으로 스크롤 + 포커스, 칸 아래에 고치는 방법.
- 모바일: 요약은 접힌 한 줄("합계 32,000원 ▾") + 하단 고정 버튼.

## 7. 빈 화면 · 오류
- 결과 없음: `EmptyState kind="no-results" query=…` + 대안 칩(필터 해제·비슷한 검색어·인기) + [필터 모두 해제].
- 처음 비어 있음: 무엇을 하면 채워지는지 + [둘러보기].
- 오류: "불러오지 못했어요" + 사용자 탓 아님 + [다시 시도]. 404는 검색칸 + 홈 링크.
- 일러스트·캐릭터 없이 48px 아이콘 하나.

## 9. 가게·공간 정보 (v0.2 — 영업시간 · 위치 · 예약)
- `SpecList align="start" labelStyle="label"`(라벨 왼쪽, 값 왼쪽 정렬)로 쓴다. 순서 고정: **영업 시간 → 주소 → 전화 → 예약 → 주차·기타**.
- 시간은 `numerals`, "화–토 18:00–23:00 · 일·월 쉬어요"처럼 한 줄에. 쉬는 날을 꼭 적는다.
- 주소 옆에 [지도에서 보기](외부 지도 앱 링크). 지도를 직접 넣으면 개인정보·API 한도를 먼저 확인(풀스택 `/external-api`).
- 예약은 외부 예약 서비스 링크가 기본. 버튼 글자는 결과를 말한다: "자리 예약하기".

## 10. 메뉴판 (v0.2)
- `MenuList`: 묶음(처음 · 불 · 끝처럼 이 가게의 말로) → 항목(이름 · 한 줄 설명 · 가격). 이름 왼쪽, 가격 오른쪽 `numerals`.
- 사진을 항목마다 붙이지 않는다. 사진은 `DragGallery` 한 줄 또는 `IndexList` 미리보기로 따로.
- "이번 계절" 같은 상태는 강조색 점 + 글자 하나(강조색의 한 가지 의미). 매운 정도·알레르기는 아이콘이 아니라 글자로.
- 가격 표기는 사이트 전체 통일: `32,000` 또는 `32,000원`. 변동가는 "시가"가 아니라 "그날 가격 — 전화로 물어봐 주세요".
- 메뉴 데이터는 페이지에 직접 쓰지 않고 `content/menu.ts`(또는 JSON)에 둔다 → 사장님이 고치기 쉽게.
