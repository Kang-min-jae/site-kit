# DESIGN.md — 디자인 플레이북 v0

> 이 문서는 **AI가 화면을 만들기 전에 반드시 읽는 규칙**이다. "~하면 좋다"가 아니라 "~한다 / ~하지 않는다"로 적었다.
> 규칙은 사용자의 레퍼런스 22개(좋음 16 · 싫음 6)에서 뽑은 **일반 원리**이고, 어느 사이트의 디자인도 옮겨 오지 않았다.
> 숫자는 `tokens.css`, 분위기 선택은 `moods.md`, 페이지 배치는 `patterns.md`, 요청 양식은 `brief.md`에 있다.

---

## 0. 읽는 순서 (AI용)

1. `brief.md` 형식의 요청을 받는다. 빠진 칸이 있으면 **5번 칸(느꼈으면 하는 단어 3개)과 1번 칸(목적)만은 반드시 묻는다.** 나머지는 이 문서의 기본값으로 채우고, 채운 값을 결과 맨 위에 적는다.
2. `moods.md`로 **프리셋(calm / friendly)과 모드(light / dark)** 를 고른다. 강조색 하나를 정한다.
3. `patterns.md`에서 필요한 페이지 패턴을 고른다.
4. `components/`의 부품만 조합해 만든다. 부품에 없는 모양이 필요하면 **새 부품을 만들고 이 문서 5장에 규칙을 추가**한다. 페이지 안에서 일회성 스타일을 만들지 않는다.
5. 13장 **완성 점검표**를 하나씩 확인하고, 통과하지 못한 항목을 고친 뒤 결과를 낸다.
6. 사용자가 고친 점은 `LOG.md`에 적고, 같은 수정이 두 번 나오면 규칙으로 올린다.

## 1. 최우선 원칙

> **목적이 3초 안에 보일 것. 그 위에서 글은 적게, 이미지는 크게, 형식은 통일, 반응은 즉시.**

| # | 원칙 | 이렇게 한다 | 이걸 피하려는 것 |
|---|---|---|---|
| P1 | 3초 안에 목적 | 첫 화면에 "무엇을, 누구를 위해" 한 문장 + 행동 하나 | 무슨 사이트인지 모르겠는 화면 (싫음 4건이 이 이유) |
| P2 | 주인공은 실제 내용물 | 첫 화면 가장 큰 자리에 작업물·상품·사용 화면 | 장식(그라데이션 덩어리·도형)이 주인공인 화면 |
| P3 | 시선 순서가 있다 | 화면마다 **1등(가장 큼) → 2등 → 나머지**가 크기·굵기·밝기로 구분됨 | 같은 무게의 입구 수십 개 |
| P4 | 형식 통일 | 같은 종류는 같은 크기·비율·정보 순서 | 카드마다 다른 모양, 흩뿌린 배치 |
| P5 | 즉시 반응 | 누르고 치면 0.2초 안에 화면이 답한다 (상태 변화·미리보기·결과) | 입력해도 아무 일 없는 화면 |

재미(둘러보는 즐거움, 움직임)는 좋아하지만 **질서(정렬·통일·적은 층) 안에서만** 허용한다. 재미가 핵심 정보보다 앞에 오지 않는다.

## 2. 디자인 값 사용 규칙

### 2.1 역할 이름만 쓴다
- 색은 `bg / surface / surface-2 / line / line-strong / ink / ink-2 / ink-3 / accent / primary / danger / success / warning / scrim / focus` 만 쓴다.
- `#hex`, `rgb()`, `red-500`, `black/40`, `text-[11px]`, `rounded-[7px]` 같은 **날것의 값과 임의 값을 페이지 코드에 쓰지 않는다.** (tokens.css에서 Tailwind 기본 팔레트·크기·모서리·그림자를 지웠으므로 대부분은 클래스 자체가 없다.)
- 새 값이 필요하면 tokens.css에 **역할 이름으로** 추가하고 이유를 주석으로 남긴다.

### 2.2 글자 크기 단계 (이 밖의 크기는 없다)

| 이름 | 크기 | 줄 간격 | 쓰는 곳 |
|---|---|---|---|
| `caption` | 12 | 1.5 | 그림 설명, 법적 문구. **12 미만 금지** |
| `label` | 13 | 1.45 | 라벨, 배지, 메타(날짜·개수) |
| `body-sm` | 14 | 1.55 | 보조 본문, 작은 버튼, 메뉴 |
| `body` | 16 | 1.6 | UI 기본 본문, 입력칸 |
| `reading` | 17 | 1.75 | 긴 글 본문 |
| `title-sm` | 20 | 1.4 | 창 제목, 큰 카드 제목, 가격(비교 목록) |
| `title` | 24 | 1.35 | 섹션 제목 |
| `title-lg` | 28 | 1.3 | 페이지 제목, 글 소제목(h2) |
| `display-sm` | 30→40 | 1.2 | 상세 페이지 상품명, 작은 히어로 |
| `display` | 36→56 | 1.15 | 랜딩 첫 문장 |
| `display-lg` | 44→80 | 1.08 | 보여주는 사이트의 첫 화면 한 줄 |

- 한 화면에 쓰는 크기는 **최대 5단계**, 굵기는 **최대 3단계**(보통 400·600·700).
- 위계는 **단계를 크게 건너뛰어** 만든다. 제목과 본문이 한 단계 차이(20/16)면 위계가 약하다 → 두 단계 이상 차이.
- 작은 글자를 남발하지 않는다. 화면 글자의 절반 이상이 `label` 이하이면 실패.

### 2.3 여백 — 4px 격자
- 간격은 Tailwind 기본 4px 단위(`1`=4px)만 쓴다. 주로 **4·8·12·16·24·32·48·64·96**.
- 관계가 가까울수록 좁게, 멀수록 넓게: 라벨↔칸 8 / 칸↔칸 20~24 / 묶음↔묶음 48 / 섹션↔섹션 96(모바일 64).
- 페이지 폭: `container-page`(최대 1200, 좌우 16/24/40). 긴 글: `container-reading`(최대 700).

### 2.4 모서리·그림자·선
- 모서리는 `control / check / chip / card / media / dialog` 6개 역할뿐. 값은 프리셋이 정한다 (calm=각지게, friendly=둥글게).
- 그림자는 `card / raised / overlay` 3단계뿐. **calm은 카드 그림자 없음**(선과 여백으로 나눈다). dark 모드는 그림자 대신 1px 선.
- 구분은 **여백 > 선 > 배경색** 순서로 먼저 쓴다. 배경색 띠로 영역을 나누는 것은 관리자·설정 화면에서만.

## 3. 프리셋과 모드

- **calm(차분하고 고급스러운)**: 크림 바탕, 각진 모서리, 밑줄 입력칸, 진한 무채색 주 버튼, 제목은 명조(Noto Serif KR), 가격은 조용하게.
- **friendly(산뜻하고 친근한)**: 밝은 무채색 바탕, 둥근 모서리, 채움 입력칸, 강조색 주 버튼, 모두 Pretendard, 가격은 크고 굵게.
- **light = 쓰는 사이트**(예약·쇼핑·글·커뮤니티·도구), **dark = 보여주는 사이트**(포트폴리오·작품·초대장·브랜드 쇼케이스).
- 고르는 법은 `moods.md`. 둘을 섞지 않는다 (한 사이트 = 프리셋 1개 + 모드 1개. 다크 모드 전환 기능은 같은 프리셋 안에서만).

### 강조색 규칙
- 사이트마다 **하나**. 그 색은 **한 가지 의미에만** 쓴다: (a) 핵심 행동(friendly 주 버튼) 또는 (b) 하나의 상태(할인·새 글·진행 중).
- 강조색으로 문장을 강조하지 않는다. 메뉴 항목마다 다른 색을 주지 않는다.
- 다른 회사의 대표 색과 같거나 아주 가까운 색을 고르지 않는다 (12장).
- **주 버튼에 채도 높은 색을 쓰지 않는다.** 선명한 초록·파랑 같은 원색 버튼은 튀고 유치해 보인다(부품 평가). 채도를 낮춘 색이나 진한 무채색으로.
- 고른 뒤 `node scripts/check-contrast.mjs design/tokens.css <사이트 css>`로 대비를 통과시킨다.

## 4. 배치와 위계

1. **주인공 하나**: 한 화면에서 가장 큰 것은 하나. UI(메뉴·버튼·필터)는 가장자리에서 조용하게.
2. **층은 최대 3개**: 바탕 → 내용 → 창(또는 알림). 창 위에 창, 고정 띠 + 떠 있는 버튼 + 알림이 동시에 겹치지 않는다.
3. **격자 위에**: 12열 격자(데스크톱), 요소의 왼쪽 끝을 맞춘다. 흩뿌린 배치·기울인 상자 금지. 의도적인 엇갈림(사진 2~3장을 높이 다르게)은 보여주는 사이트의 한 섹션에서만.
4. **같은 행동은 한 번**: 한 화면에 같은 버튼(예: "문의하기")을 두 번 이상 두지 않는다. 긴 페이지 끝의 반복 1회만 예외.
5. **옆 단은 최대 하나**: 본문 + 옆 단(필터·목차·요약) 2단까지. 양옆에 글이 가득한 3단 금지.
6. **입구는 5개 안팎**: 주 메뉴 ≤5, 첫 화면의 갈래 ≤3. 나머지는 묶어서 한 번 더 들어가게.
7. **글자와 그림을 겹치지 않는다**: 이미지·무늬 위에 글을 올릴 땐 단색 바탕 또는 충분한 어둡게 깔기(대비 4.5:1)로 읽히게 한다. 작은 화면일수록 겹치지 않게.

## 5. 부품 규칙 (요약 — 자세한 건 각 파일 머리말)

| 부품 | 꼭 지킬 것 |
|---|---|
| `Button` | primary는 화면당 1개. 글자 1~3단어, 결과를 말한다("결제하기 32,000원"). 잠김은 `disabledReason`으로 이유+방법. 처리 중엔 폭 유지 + 회전 표시 |
| `IconButton` | `label` 필수. 44×44 |
| `TextField` | 이름은 칸 위, 예시는 placeholder("예: …"), 오류는 아이콘+고치는 방법. 선택 입력만 "선택" 표시. 비밀번호는 보기 버튼(확인 칸 없음) |
| `Select` | 옵션 2~7개. 8개 이상·검색 필요 → SearchBox |
| `Checkbox` / `ConsentGroup` | 모두 동의 → 필수 → 선택 순. **필수는 진한 테두리 표시 + 진한 글자, 선택은 흐리게** (색이 아니라 진하기로). 선택 묶음엔 "동의하지 않아도 가입할 수 있어요". 선택 항목 미리 체크 금지 |
| `Chip` | 선택은 색이 아니라 진하기·굵기 |
| `Badge` | 카드당 최대 1개. 강조색 배지는 강조색의 "한 가지 의미"일 때만 |
| `Tabs` | 글자 탭 + 선택 밑줄. 상자 탭·배경 띠 탭 금지. 5개 넘으면 가로 스크롤 |
| `MediaCard` | 같은 목록 = 같은 비율·같은 정보 순서. browse는 이미지+제목+한 줄. compare는 가격 최대. 품절은 흐리게 두고 빼지 않음 |
| `Dialog` | 제목 필수. [취소] [주 행동] 오른쪽 아래. 창 안에 창 금지. 모바일은 아래 시트. **삭제 확인은 지울 대상을 목록으로 보여주고 하나씩 고를 수 있게**, 버튼에 개수("2개 삭제"), 지운 뒤 토스트에 되돌리기 |
| `Drawer` | 메뉴 버튼은 오른쪽 위 하나. 폭은 내용에 맞게(256~320px). 항목 크게, 구분선 대신 여백. 현재 페이지는 굵게+점 |
| `Toast` | 한 번에 하나, 해요체 한 줄, 4초. 사용자가 고쳐야 하는 오류는 토스트가 아니라 칸 아래 |
| `EmptyState` | 상황(검색어 다시 보여주기) + 대안 + 다음 행동 하나. 큰 일러스트 금지 |
| `SearchBox` | 누르면 최근·인기, 2글자부터 미리보기 ≤5 + 전체 결과 보기. 일치 글자 굵게. 한글 조합 중 Enter 무시 |
| `SiteHeader` | 메뉴 ≤5, 같은 색·굵기, 현재만 진하게. 행동 버튼 ≤1. 위 광고 띠 금지. 메뉴 버튼은 아이콘 또는 글자(`menuLabel`) — 사이트 분위기로 고른다 |
| `Stepper` | 3~5단계. 모바일은 "2 / 3 · 이름" + 진행 막대 |
| `Skeleton` | 실제 모양과 같은 자리. 0.3초 안에 끝나면 보여주지 않음 |
| `ResultBar` | 왼쪽 "총 N개", 오른쪽 정렬, 켜진 필터는 칩으로 하나씩 해제 + 모두 해제 |
| `Dropzone` | 받는 형식·크기 한도를 영역 안에. 끌어다 놓는 중엔 진해짐. 오류는 아래에 아이콘+고치는 방법. 형식 검사는 서버가 다시 |
| `SpecList` | 라벨-값 표(R19). 라벨 작은 대문자 왼쪽, 값 오른쪽·숫자 자리 맞춤, 줄마다 얇은 선. 단위는 값 옆에 작게 |
| `ProgressBar` | 0.3초 넘는 작업만. 지금 단계 문장 + 퍼센트, 막대는 뒤로 가지 않음 |

## 7. 문구 규칙

- **해요체**로 통일한다. "저장했어요", "다시 시도해 주세요". 반말·습니다체 섞지 않는다.
- 첫 화면 큰 문장은 **구체적으로**: 무엇을 + 누구에게/어떻게. "오늘의 가능성", "We are ○○", "본질과 가치" 같은 **어느 회사에나 붙는 문장 금지**.
- 버튼은 1~3단어 동사형: "예약하기", "다음", "담기". "확인"은 정말 확인만 할 때.
- 라벨은 사람이 읽는 말: `prd_cat_01` ✗ → "상의" ✓. 파일명·코드명 노출 금지.
- 오류 문장 = 무슨 일 + 어떻게 고치는지. 사용자를 탓하지 않는다. "잘못 입력하셨습니다" ✗ → "휴대폰 번호는 숫자만 입력해 주세요" ✓
- 숫자는 천 단위 쉼표, 가격은 "32,000원", 날짜는 "10월 25일 (일)" 형태.
- 모든 문구는 이 사이트를 위해 새로 쓴다. 레퍼런스 사이트의 문장을 옮기지 않는다.

## 8. 움직임

| 이름 | 시간 | 쓰는 곳 |
|---|---|---|
| 빠름 | 150ms | hover, 색 변화, 체크 |
| 기본 | 200ms | 탭 밑줄, 입력칸 밑줄, 패널 나타남 |
| 등장 | 240~280ms | 창·시트·토스트 들어옴 (나갈 때는 더 빠르게) |
| 강조 | 300ms | 카드 이미지 살짝 확대(1.03) |

- 곡선은 `ease-standard`(빠르게 시작, 부드럽게 멈춤).
- **움직임은 사용자 행동에 대한 반응일 때만.** 혼자 계속 번쩍이거나 도는 장식 금지. 자동 재생 슬라이드 금지.
- 스크롤을 가로채지 않는다(휠 한 번에 화면 한 장 넘기기 금지). 스크롤에 따라 나타나는 효과는 섹션당 1회, 0.3초 이내.
- `prefers-reduced-motion`이면 모든 움직임을 끈다 (tokens.css에 이미 있음).
- 마우스를 따라다니는 커서 장식 금지.

## 9. 이미지·영상

- **사이트 소유이거나 사용권이 확인된 것만** 쓴다(직접 촬영, 구매, 라이선스가 명시된 무료 이미지). 출처와 라이선스를 `public/images/CREDITS.md`에 적는다.
- 레퍼런스 사이트의 이미지·로고·아이콘·일러스트를 **임시로라도 넣지 않는다.** 정해지기 전엔 `ImagePlaceholder`.
- 한 목록 안의 이미지는 같은 비율·같은 바탕. 기본 비율: 상품 4/5, 작품 3/2, 포스터 2/3, 썸네일 1/1.
- 영상은 소리 꺼짐 + 정지 버튼 + 첫 프레임 이미지(poster) + 움직임 줄이기 사용자에겐 정지 이미지. 파일은 영상 CDN에서.
- AI로 만든 이미지도 특정 작가·브랜드·캐릭터를 흉내 내지 않는다.

## 10. 접근성 최소 기준 (통과 못 하면 완성 아님)

- 글자 대비 4.5:1, 부품 경계·포커스 3:1 — `check-contrast.mjs`가 확인.
- 누르는 것은 44×44 이상(모바일). 키보드만으로 모든 기능 사용 가능, 포커스 표시는 한 겹.
- 이미지에 `alt`, 아이콘 버튼에 `label`, 입력칸에 연결된 이름.
- 색만으로 의미를 전하지 않는다(오류 = 색 + 아이콘 + 문장).
- 한국어 문서: `<html lang="ko">`, 한글 줄바꿈 `keep-all`(tokens.css 기본).

## 11. 하지 않을 것

1. 목적을 가리는 컨셉 화면 ("데스크톱처럼", "예술 작품처럼", 3D 공간 탐험)
2. 장식이 주인공인 첫 화면 — 파스텔 그라데이션 덩어리, 의미 없는 원·궤도 선, 떠다니는 도형
3. 주인공과 시선을 다투는 배경 — 강한 방사형 빛, 반복 로고 무늬, 고대비 전체 무늬
4. 혼자 번쩍이는 연출, 자동 슬라이드, 따라다니는 커서
5. 기괴하거나 충격적인 이미지·캐릭터
6. 한 화면 4층 이상 (배경+내용+창+알림+도구바…)
7. 흩뿌린 배치, 격자 무시
8. 같은 행동 버튼 반복
9. 파일명·코드명 라벨, 작은 글자 남발(12px 미만 금지)
10. 질감·대비·여백 없이 회색 면으로만 나눈 위계, 화면 폭 전체의 회색 메뉴 띠
11. 양옆 사이드바까지 글로 가득 찬 3단
12. 같은 무게의 입구 수십 개 (로고 벽, 긴 메뉴 줄)
13. 서로 다른 스타일을 한 격자에 모으기 (꼭 필요하면 같은 크기·단색)
14. 빨간 글씨·화살표로 문장 강조, 메뉴 항목별 다른 색
15. 모든 카드에 날짜·조회수·아이콘 줄줄이
16. 맨 위 광고·배너 띠
17. 입력해도 반응 없는 검색칸
18. 어느 회사에나 붙는 추상 문구 (오늘·내일·가능성·가치·본질)
19. 실제 내용을 스크롤 뒤로 미루는 첫 화면
20. 휠을 여러 번 굴려야 넘어가는 소개(스크롤 가로채기)
21. 순백(#fff) 바탕, 순흑(#000) 바탕
22. **흔한 AI 디자인 공식** — 아무 지시 없을 때 자동으로 나오는 조합은 "어디서 본 것" 같아 보인다:
    크림 바탕 + 명조 제목 + 테라코타 강조색을 한꺼번에, 보라→파랑 그라데이션 히어로, 기본 남보라(인디고) 버튼,
    이모지를 섹션 표시로, 모든 것을 가운데 정렬, 모든 상자에 같은 둥근 모서리+그림자, 카드 왼쪽 강조 막대.
    (calm 프리셋은 크림 바탕+명조를 쓰므로 강조색은 반드시 다른 계열로 고른다)

## 12. 저작권·독창성 규칙

레퍼런스는 **"무엇이 왜 좋은지"를 배우는 자료**일 뿐, 가져오는 재료가 아니다.

### 가져오는 것 (아이디어 · 일반 원리)
- "필터는 왼쪽, 결과는 오른쪽" 같은 **업계 공통 관례**
- "강조색은 한 가지 의미에만" 같은 **원리**
- "본문 폭 700, 줄 간격 1.75" 같은 **숫자 범위** (이 플레이북에서 새로 정한 값)

### 가져오지 않는 것 (표현)
- 이미지·사진·영상·일러스트·캐릭터·아이콘·로고·워드마크
- 회사의 대표 색, 전용 글꼴, 특유의 무늬
- 문구(카피), 이름, 슬로건
- 특정 화면의 배치를 그대로 옮긴 구성, 코드(HTML/CSS/JS), 애니메이션 타이밍 복제
- **시그니처 연출** — 그 사이트를 떠올리게 하는 단 하나의 장치(예: 휘어진 무한 격자, 화면을 가로지르는 거대 로고 글자, 특정 마스코트)

### 쓰는 자원의 라이선스
- 글꼴: Pretendard, Noto Serif KR — 모두 **SIL Open Font License 1.1** (상업 사용·웹 임베드 가능, 글꼴 파일 자체 판매 금지).
- 아이콘: `components/icons.tsx` — 이 플레이북에서 직접 그린 단순 도형.
- 이미지: 9장 기준.
- 외부 부품 라이브러리 코드를 복사해 넣지 않는다. 쓰려면 패키지로 설치하고 라이선스를 `CREDITS.md`에 적는다.

### 독창성 점검 (완성할 때마다)
1. 이 화면을 보고 **특정 사이트 하나가 떠오르는가?** → 떠오르면 그 사이트를 떠올리게 한 요소(색·배치·연출·문구)를 바꾼다.
2. brief의 "참고한 느낌"에 적힌 사이트와 **나란히 놓았을 때** 색·배치·문구가 겹치는 곳이 없는가?
3. 화면 안의 모든 이미지·아이콘·글꼴·문구의 **출처를 말할 수 있는가?** (직접 만듦 / 라이선스 확인 / 자리 표시)
4. 강조색이 유명 서비스의 대표 색과 구분되는가?
→ 하나라도 "아니오"면 완성이 아니다.

> 이 문서와 취향 프로필은 레퍼런스를 **번호와 유형**으로만 기록한다. 회사 이름·화면 캡처를 플레이북 파일에 넣지 않는다.

## 13. 완성 점검표 (design-review 스킬이 이 순서로 확인)

**목적**
- [ ] C1. 첫 화면만 보고 3초 안에 "무슨 사이트, 무엇을 하면 되는지" 말할 수 있다
- [ ] C2. 첫 화면의 가장 큰 것이 실제 내용물이다
- [ ] C3. 큰 문장이 이 사이트에만 맞는 구체적인 말이다

**위계**
- [ ] C4. 화면마다 1등이 하나다 (가장 큰 것, primary 버튼 각각 1개)
- [ ] C5. 층 3개 이하, 옆 단 1개 이하, 주 메뉴 5개 이하
- [ ] C6. 같은 종류의 카드·목록 형식이 모두 같다
- [ ] C7. 같은 행동 버튼이 반복되지 않는다

**값**
- [ ] C8. 페이지 코드에 날것의 색·임의 값이 없다 (`grep -E "\[(#|[0-9]+px)|#[0-9a-fA-F]{3,6}\b"` 결과 0)
- [ ] C9. 강조색이 한 가지 의미에만 쓰였다
- [ ] C10. 12px 미만 글자가 없고, 작은 글자가 절반을 넘지 않는다
- [ ] C11. 대비 스크립트 통과

**반응**
- [ ] C12. 모든 누르는 것에 hover·포커스·누름 상태가 있다
- [ ] C13. 입력·검색이 즉시 반응한다, 잠긴 버튼은 이유를 말한다
- [ ] C14. 빈 화면·오류 화면이 다음 행동을 준다

- [ ] C17. 누르는 것 44px 이상, 글자와 이미지가 겹치지 않는다
