# 사이트 요청서

> "이 사이트를 이런 느낌으로 만들어줘"를 이 한 장으로 보낸다. **★ 칸만 채워도 시작할 수 있다.**
> 위쪽(디자인)은 디자인 플레이북의 `design/brief.md`와 같고, 아래쪽(풀스택)은 `AGENTS.md` 0장으로 옮겨 적는다.
> 빈 칸은 각 플레이북의 기본값으로 채우고, 무엇으로 채웠는지 결과 맨 위에 적는다.
> 비밀 키·DB 주소·회원 정보는 이 요청서에 쓰지 않는다.

```markdown
# 사이트 요청서 — <사이트 이름>

## 무엇을
1. ★ 목적 (한 문장: 누가, 여기서 무엇을 하나)
2. ★ 주 사용자 (누구, 어떤 기기 — 모바일 비율)
3. ★ 첫 화면에서 할 행동 하나
4. 필요한 페이지 (아는 만큼)

## 디자인 (→ design/)
5. ★ 느꼈으면 하는 단어 3개
6. 이런 느낌은 싫다
7. 참고한 느낌 (링크 또는 취향 프로필 번호 — 원리만 참고, 색·이미지·문구·배치는 가져오지 않는다)
8. 이미 정해진 것 (이름·로고 파일, 강조색, 사진 보유 여부, 꼭 들어갈 문구)

## 기능과 운영 (→ AGENTS.md 0장)
9.  로그인: (없음 / 이메일 / 소셜 — 구글·카카오·네이버) · 관리자 화면 여부
10. 결제: (없음 / 단건 / 정기 — PG사)
11. 파일 업로드: (없음 / 이미지 / 문서 — 공개·비공개)
12. 외부 API: (이름, 하루·분당 한도, 초기화 시각)
13. 수집하는 개인정보와 이유: (꼭 필요한 것만)
14. 알림: (이메일·문자·푸시 — 광고성 포함 여부)
15. 스택·호스팅: (기본값: 재사용 키트 — Next.js · Vercel · Postgres)
16. 요금제 한도: (서버 실행·이미지 변환·DB 전송량·저장 용량)
17. 서버·DB·저장소 지역, 기준 시간대: (기본값: 가까운 지역, Asia/Seoul)
18. 예상 규모: (하루 방문자, 데이터 양 — 대략)
19. 출시 날짜·꼭 먼저 나와야 하는 것
```

## 작성 예시

```markdown
# 사이트 요청서 — 모퉁이책방

1. 독립 출판 책을 소개하고 온라인으로 파는 작은 서점
2. 책 좋아하는 20~30대, 모바일 60%
3. 이번 달 들어온 책 둘러보고 장바구니 담기
4. 홈 / 책 목록 / 책 상세 / 장바구니·결제 / 서점 일기(글) / 로그인 / 마이페이지 / 관리자(재고)
5. 조용한 · 잡지 같은 · 따뜻한
6. 대형 서점처럼 빽빽한 화면, 할인 배너
7. 취향 프로필 R12(상세: 사진 크게 + 정보 고정), R10(글 읽기)
8. 이름 "모퉁이책방", 표지 사진 직접 촬영 예정, 강조색 미정
9. 이메일 + 카카오, 관리자 1명
10. 단건 결제 (PG사 미정)
11. 관리자만 표지 이미지 업로드(공개)
12. 없음 (도서 정보는 직접 입력)
13. 이메일(로그인), 이름·전화번호·주소(배송)
14. 주문·배송 알림 메일. 신간 소식 메일은 광고성 → 별도 동의
15. 기본값
16. 무료 요금제로 시작
17. 기본값
18. 하루 100~300명, 책 500권 이하
19. 12월 첫 주. 목록·상세·결제가 먼저
```
