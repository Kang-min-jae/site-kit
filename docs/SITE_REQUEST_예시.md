# 사이트 요청서 — 양식 설명과 작성 예시

> 저장소 루트의 `SITE_REQUEST.md`(빈 양식)를 채울 때 보는 설명과 예시다. **★ 칸만 채워도 시작할 수 있다.**
> 위쪽(디자인)은 디자인 플레이북 v0.2의 `design/brief.md`와 **칸 번호까지 같고**, 아래쪽(풀스택, F1~F14)은 `AGENTS.md` 0장으로 옮겨 적는다.
> brief.md의 9번(기능)은 여기서 F1~F14로 펼쳐 쓴다. 두 파일의 디자인 칸이 어긋나면 brief.md를 기준으로 맞춘다.
> 빈 칸은 각 플레이북의 기본값으로 채우고, 무엇으로 채웠는지 결과 맨 위에 적는다.
> 비밀 키·DB 주소·회원 정보는 이 요청서에 쓰지 않는다.

```markdown
# 사이트 요청서 — <사이트 이름>

## 무엇을
1. ★ 목적 (한 문장: 누가, 여기서 무엇을 하나)
2. ★ 주 사용자 (누구, 어떤 기기 — 모바일 비율)
3. ★ 첫 화면에서 할 행동 하나
4. 필요한 페이지 (아는 만큼)

## 디자인 (→ design/, brief.md와 같은 번호)
5. ★ 느꼈으면 하는 단어 3개
6. 이런 느낌은 싫다
7. 참고한 느낌 (링크 또는 취향 프로필 번호 — 원리만 참고, 색·이미지·문구·배치는 가져오지 않는다)
8. 이미 정해진 것 (이름·로고 파일, 강조색, 사진 보유 여부, 꼭 들어갈 문구)
10. 디렉션: (house / editorial / object / 없음 — 모르면 비워 둔다 → design/directions.md 0장)
11. 시그니처 장면 한 줄: (선택 — 이 사이트를 기억하게 할 장면 하나)
12. 소재 상태: (사진·영상·3D — 있음 · 촬영 예정 · 없음 → 시안은 직접 렌더한 소재로, 납품 전 교체)

## 기능과 운영 (→ AGENTS.md 0장)
F1.  로그인: (없음 / 이메일 / 소셜 — 구글·카카오·네이버) · 관리자 화면 여부
     → 로그인·DB가 모두 없으면 **작은 사이트**(AGENTS.md 20장, CHECKLIST L장)
F2.  결제: (없음 / 단건 / 정기 — PG사)
F3.  파일 업로드: (없음 / 이미지 / 문서 — 공개·비공개)
F4.  외부 API: (이름, 하루·분당 한도, 초기화 시각)
F5.  AI 기능: (없음 / 있음 — 무엇을, 근거 자료, 하루 비용 상한 → 18장)
F6.  수집하는 개인정보와 이유: (꼭 필요한 것만)
F7.  알림: (이메일·문자·푸시 — 광고성 포함 여부)
F8.  스택·호스팅: (기본값: 재사용 키트 — Next.js · Vercel · Postgres / 작은 사이트면 정적 생성, DB 없음)
F9.  요금제 한도: (서버 실행·이미지 변환·DB 전송량·저장 용량)
F10. 서버·DB·저장소 지역, 기준 시간대: (기본값: 가까운 지역, Asia/Seoul)
F11. 예상 규모: (하루 방문자, 데이터 양 — 대략)
F12. 내용을 누가 고치나: (개발자 / 고객이 직접 — 메뉴·시간·공지 등 → 20장)
F13. 외주라면: 고객, 계정·도메인 소유자, 인계 날짜, 유지보수 범위·기간, 포트폴리오 사용 허락 (→ 21장)
F14. 출시 날짜·꼭 먼저 나와야 하는 것
```

## 작성 예시

```markdown
# 사이트 요청서 — 모퉁이책방

1. 독립 출판 책을 소개하고 온라인으로 파는 작은 서점
2. 책 좋아하는 20~30대, 모바일 60%
3. 이번 달 들어온 책 둘러보고 장바구니 담기
4. 홈 / 책 목록 / 책 상세 / 장바구니·결제 / 서점 일기(글) / 로그인 / 마이페이지 / 관리자(재고)
5. 조용한 · 잡지 같은 · 따뜻한
6. 대형 서점처럼 빽빽한 화면, 할인 배너
7. 취향 프로필 R12(상세: 사진 크게 + 정보 고정), R10(글 읽기)
8. 이름 "모퉁이책방", 표지 사진 직접 촬영 예정, 강조색 미정
10. 없음 (쇼핑이 주인) · 11. 표지가 책장에서 하나씩 앞으로 나온다 · 12. 표지 사진 촬영 예정
F1. 이메일 + 카카오, 관리자 1명
F2. 단건 결제 (PG사 미정)
F3. 관리자만 표지 이미지 업로드(공개)
F4. 없음 (도서 정보는 직접 입력)
F5. 없음
F6. 이메일(로그인), 이름·전화번호·주소(배송)
F7. 주문·배송 알림 메일. 신간 소식 메일은 광고성 → 별도 동의
F8. 기본값 · F9. 무료 요금제로 시작 · F10. 기본값
F11. 하루 100~300명, 책 500권 이하
F12. 관리자 화면에서 직접 · F13. 해당 없음(내 사이트)
F14. 12월 첫 주. 목록·상세·결제가 먼저
```

→ AI의 첫 줄 예) `preset=calm · mode=light · accent=올리브 계열(새로 들어온 책 표시에만) · 결제·업로드·개인정보 장(14·15·16) 적용 · CHECKLIST A·B·I·J·K`

### 작은 사이트 · 외주 예시 (v3)

```markdown
# 사이트 요청서 — 여울 (서촌 작은 식당, 외주)

1. 서촌 골목 2층 식당. 메뉴와 분위기를 보고 자리를 예약하게 하는 사이트
2. 25~45세, 지도 앱·인스타그램을 거쳐 오는 모바일 손님 80%
3. 이번 계절 차림을 보고 자리 예약하기 (외부 예약 서비스로 연결)
4. 한 페이지: 첫 화면 / 공간 / 메뉴 / 방문 정보
5. 분위기 있는 · 따뜻한(공간) · 절제된
6. 프랜차이즈 같은 밝은 색, 음식 사진 콜라주
8. 이름 "여울 YEOUL", 강조색 미정
10. house · 11. 촛불 아래 정물이 화면 아래에서 드러난다 · 12. 사진 촬영 예정 → 시안은 렌더
F1. 없음 · F2. 없음 · F3. 없음
F4. 없음 (예약·지도는 외부 링크)
F5. 있음 — 메뉴판 영어·일본어 번역을 빌드할 때 한 번 생성, 사장님 검수 후 공개 (실시간 호출 없음)
F6. 없음 (문의는 전화·인스타그램)
F7. 없음
F8. 정적 생성 · Vercel 무료 · DB 없음
F9. 무료 요금제 · 이미지 변환은 빌드 때 미리 (종량제 변환 끄기)
F10. 기본값 · F11. 하루 50~200명
F12. 사장님이 메뉴·영업시간을 직접 — content 파일(또는 구글 시트)
F13. 고객: 여울 사장님 · 도메인 등록자 = 가게 명의 · 계정은 프로젝트 전용 이메일 · 인계 12월 말 · 무상 관리 3개월 · 포트폴리오 사용 허락 받음
F14. 11월 셋째 주. 첫 화면·메뉴·방문 정보
```

→ AI의 첫 줄 예) `preset=calm · direction=house · mode=light(+dark 섹션 1) · 작은 사이트(20장) · AI 빌드 시점 번역(18장) · 인계(21장) · CHECKLIST A(해당 줄만)·L·M·N`
