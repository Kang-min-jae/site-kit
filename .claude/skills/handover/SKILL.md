# 인계 절차 (스택 무관) — AGENTS.md 21장

비밀 값(비밀번호·API 키·토큰·DB 주소)은 열지도, 출력하지도, 문서에 적지도 않는다. 계정은 **이름과 용도만** 다룬다.

## 1. 시작할 때 (첫날)

- 계정을 이 사이트 전용 이메일로 만들었는지 확인한다: 호스팅 · 도메인 · 저장소 · 분석 도구 · 지도·예약 등 외부 서비스. 내 개인 계정에 있으면 옮길 목록에 적는다.
- 도메인 등록자 = 고객 명의인지, 결제 수단·자동 갱신·만료일을 확인한다.
- 계약서 점검 항목을 사용자에게 보여 준다(법률 자문 아님): 유지보수 범위·기간, 사진·글·로고 권리, 포트폴리오 사용 허락, 비용 부담.

## 2. 인계 문서 만들기 — `HANDOVER.md`

고객이 읽는 말(해요체, 전문 용어는 한 줄 설명)로 쓴다.

| 칸 | 내용 |
|---|---|
| 계정 목록 | 서비스 · 로그인 이메일 · 소유자 · 갱신일·요금 · 이 계정으로 하는 일 |
| 도메인·DNS | 등록 업체, 만료일, 연결된 호스팅, 이메일 관련 기록이 있으면 무엇인지 |
| 내용 고치는 법 | 어느 파일·시트를 고치면 되는지, 고친 뒤 사이트에 반영되는 방법과 걸리는 시간 |
| 같이 바꿀 곳 | 영업시간·주소·전화를 바꿀 때: 사이트 · 지도 서비스 가게 정보 · 예약 서비스 (AGENTS.md 20장) |
| 배포 | 자동인지, 누가 무엇을 눌러야 하는지 |
| 문제가 생기면 | 사이트가 안 열릴 때 확인할 것 3가지, 비상 연락처 |
| 유지보수 | 범위·기간, 그 이후 연락 방법 |
| 소재 권리 | 사진·글·글꼴·음원의 출처(CREDITS 요약), 시안 소재가 남아 있지 않은지 |

## 3. 함께 한 번 해 본다

- 고객과 메뉴 한 줄 바꾸기 → 반영 확인을 실제로 해 본다. 막히면 그 부분의 문서를 고친다.
- 비밀번호는 고객이 직접 바꾸게 한다(또는 비밀번호 관리자 공유). 채팅·메일로 보내지 않는다.

## 4. 끝낼 때

- 내 접근 권한 목록을 만든다: 호스팅 팀원, 저장소 협업자, 도메인 관리자, 분석 도구, 외부 서비스. 유지보수가 끝나는 날 뺀다.
- 뺀 목록과 날짜를 고객에게 알리고, 인계 문서 맨 아래에 기록한다.
