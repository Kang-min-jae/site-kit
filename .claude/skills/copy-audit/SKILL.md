# 옮기기 전 점검 절차 (스택 무관)

원본 저장소는 **읽기만** 한다. 고칠 것이 있으면 결과표에 적고, 원본을 고칠지는 사용자에게 묻는다.

## 1. 실수 목록 만들기

원본의 회고 문서, 사고 기록, 규칙집의 "왜" 줄, 고친 커밋(fix·revert)에서 실수를 모으고, 실수마다 코드에서 찾는 방법을 정한다.

| 흔한 실수 | 찾는 법(예) |
|---|---|
| 전체 캐시 삭제 | 루트·전체 경로 무효화, 모든 키 삭제(`allEntries`), 전체 purge |
| 실패를 캐시하거나 빈 값으로 삼킴 | `catch` 뒤 `null`·`[]` 반환, 로그 없는 `catch` |
| 일시 실패가 "없음"(404)으로 | 외부 호출 실패가 "없음" 처리로 이어지는 경로 |
| 같은 규칙의 복사본 | 도우미 함수가 있는데 같은 조건식이 여러 파일에 직접 있음 |
| 타임아웃 없는 외부 호출 | 서버 쪽 HTTP 호출 옵션 |
| 목록에서 모든 열 읽기 | 열 지정 없는 목록 쿼리, `SELECT *` |
| 공통 틀에서 사용자 정보 읽기 | 레이아웃·헤더·전역 미들웨어의 세션·쿠키 접근 |
| 권한 확인 없는 쓰기 | 쓰기 핸들러의 첫 줄 |
| 쓰지 않는 의존성 | 패키지 목록의 각 이름을 코드의 import에서 검색 |
| 빌드는 되지만 결과가 깨진 설정 | 만들어진 CSS·JS·응답 헤더를 직접 열어 확인(예: hover 규칙이 깨진 CSS) |

## 2. 원본 코드 점검

결과를 표로 남긴다: **회고의 실수 | 지금 코드(파일:줄) | 판정(해결 · 남음 · 주의) | 옮길 때 할 일**.
"해결"도 한 파일만 보지 말고 전체 검색으로 모든 곳에 적용됐는지 확인한다.

## 3. 비밀 값은 옮기지 않는다 — 설정 이름 목록만

- 비밀 값(비밀번호·API 키·서명 키·DB 주소·토큰·인증서)을 열거나 출력하거나 복사하지 않는다. `.env`·키 파일은 열지 않는다. 이름은 코드와 `.env.example`에서 찾는다.
- 코드가 읽는 설정 이름을 모은다: 환경 변수 읽기, 설정 파일 자리표시자, 라이브러리가 자동으로 읽는 이름(인증 라이브러리 등), 배포 스크립트.
- 표로 만든다: **이름 | 용도 | 발급처 | 필수/선택 | 환경 | 플랫폼이 자동으로 넣는지**.
- 값이 아닌 다시 할 설정도 적는다: OAuth 콜백 주소, 메일 발송 도메인 인증, 방화벽 규칙, 호스팅 환경 변수 범위.
- 새 프로젝트의 `.env.example`에는 이름만(값은 비우거나 로컬 전용 가짜 값) 둔다. 키는 새로 발급받는다.

## 4. 옮길 목록과 마무리

- 옮길 파일 목록에서 뺀다: `.env*`(예시 제외), 키·인증서, 로그, DB 덤프·실제 회원 정보, 빌드 결과물, 업로드 파일.
- 원본 전용 이름·도메인·연락처를 바꿀 목록을 만든다.
- 남은 실수는 고친 뒤 옮기거나 옮기면서 고친다 — 그대로 옮기지 않는다.
- 옮긴 뒤 새 저장소에서 비밀 값 검사(키 모양 문자열, 추적되는 `.env` 파일)를 돌리고 결과를 보고한다.
